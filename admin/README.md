# 心灵信箱 · Web 管理后台

纯静态单页后台（无构建步骤），部署到 CloudBase **静态网站托管**，通过 `admin` 云函数读写云数据库。管理主题（themes）、信纸版式（papers）、用户（users）、会员状态（members）与会员专属内容（member_items）、问题反馈（feedback）、数据看板与用户统计。

> **隐私红线**：本后台不提供任何信件正文/回信内容的查看能力，所有统计均为计数聚合。这是产品「内容属于用户」原则的一部分，改动时不得破坏。**唯一例外是 `feedback`**：用户主动提交给开发者的问题反馈（正文 + 截图），仅在「问题反馈」板块展示。

## 排序与会员专属标记（主题管理 / 版式管理）

**拖动块排序**：每行行首有一个六点拖动块，按住上下拖动即可改顺序（行随指针实时挪位，松手生效）。

- 松手时把「当前视觉顺序」写成 `sort = 0..n-1`，**只回写值真的变了的行** —— 挪一格通常只有 2–3 个请求，不会整表重写。
- 只点一下不拖 → 不打任何接口、不动数据；保存失败会 Toast 报错并重新拉取列表（界面回到服务端的真实顺序，不会显示一个未落库的顺序）。
- 右侧 `↑ ↓` 箭头保留：单步微调、以及拖动不便时的备用入口（两者改的是同一个 `sort`，可混用）。
- 拖动块用 Pointer Events 实现，鼠标与触屏同一套代码（触屏上按住拖动块不会误触发页面滚动）。

**「👑 会员」标签**：同一个 id 在 `member_items`（会员管理 → 专属内容）里已有专属款时，状态列在「上架/下架」前多挂一枚金色标签。

- 判断只看「`member_items` 里有没有这条同 id 的记录」，**不看该记录自身是否上架**（那是「专属内容」Tab 的事，避免同一格混两个来源的上下架）。`themeList` / `paperList` 会并行查一次 `member_items` 给出 `premium` 标记，与 `theme` 云函数下发列表时的 `premium` 同源。
- 该标记**不入库**：`themeSave` / `paperSave` 走 `pick` 字段白名单，`premium` 不会被写进 `papers` / `themes` 文档。
- **为什么有时看不到这个标签**：它只在「同 id」时才出现。官方 seed 的专属款用的是新 id（`gold` / `canglan` / `yinxiang`），这些 id 只存在于 `member_items`、不在 `papers` / `themes` 里，所以这两页不会出现它们（对应条目在「会员管理 → 专属内容」维护）。给已有款做专属版时要走「专属内容 → ＋ 新建 → 来源：从已有款挑选」，后台会复用原 id —— 那正是「这一款已经是专属款」的情形，标签就会出现。
- **顺序的实际作用域**：`theme` 云函数下发时是「官方款全在前（各按自己的 sort）→ 同 id 专属款原位覆盖 → 新 id 专属款追加末尾」（`cloudfunctions/theme/index.js` 的 `mergeLists`），所以**只存在于专属内容的新 id 款永远排在列表末尾**，它在「专属内容」里填的 `sort` 改不了自己前面的款。要改变整条列表的顺序，只能调 `papers` / `themes` 的 `sort` —— 即这两页的拖动块。
- 另外：这两页列出的是**全部状态**的行（含已下架），而小程序只渲染上架的。拖动是从整张表的顺序出发重新编号 `sort`，所以「拖到某行前面」在小程序里一定成立，不会像 `↑` 那样遇到下架款「按了没反应」。

## 鉴权

- 管理员密钥只读云函数环境变量：控制台点函数名 `admin` 进详情 →「函数配置」→ 编辑环境变量，新增 `ADMIN_KEY`（值填强随机串）。
- 未配置 `ADMIN_KEY` 时云函数拒绝一切请求（fail closed），后台无法登录。
- 密钥不落入仓库：代码里没有任何内置密钥，忘记或怀疑泄露时在控制台直接改成新值即可（等于轮换密钥）。
- Web 端拿不到微信 openid，白名单以密钥形式落地；请使用强随机串。
- **跨域来源**：环境变量 `ADMIN_ORIGIN`（多个用英文逗号分隔）配置后，云函数只对白名单来源回 `Access-Control-Allow-Origin`，其余来源浏览器侧直接拒绝。建议填静态托管域名（如 `https://xxx.tcloudbaseapp.com`）；留空回落 `*`（兼容旧部署，但会放大暴力破解面）。
- **限流（上线必做）**：HTTP 网关路由是公开的，云函数内没有分布式限速能力 —— 请在**网关/云开发侧为 `/admin` 路由配置访问频率限制或 IP 白名单**，并定期轮换 `ADMIN_KEY`（控制台改值即完成轮换）。

## 部署步骤（从头到尾完整清单）

1. **配密钥**：控制台 → 云函数 `admin` →「函数配置」→ 环境变量，新增 `ADMIN_KEY`（强随机串，见上节）。密钥只存在控制台环境变量里，不要写进代码提交。
2. **部署云函数**：微信开发者工具 → cloudfunctions 目录 → 右键 `admin`「上传并部署：云端安装依赖」；`theme` 有改动（新增 papers action），同样重新部署。部署完在控制台云函数列表能看到 `admin` 状态正常。
3. **建 HTTP 网关路由**：控制台 →「HTTP 网关」→ 路由管理 →「添加该域名路由」：路由路径填 `/admin`，资源类型选**云函数**，资源对象选 `admin`，**跨域设置开启**（允许跨域，静态页才能调用），身份认证选**关闭/无需认证**（鉴权由密钥承担）。保存后得到路由地址：`默认域名 + /admin`。**同页为该路由配置访问频率限制**（见「鉴权」一节）。
4. **填路由地址**：编辑 `admin/app.js` 顶部 `CONFIG.API_URL`，把上一步的完整地址填进去。
5. **上传前端**：控制台 →「静态网站托管」→ 文件管理，在**根路径**上传 `index.html`、`style.css`、`app.js`（注意是「上传文件」且当前路径为 `/`；若 `index.html` 不在根路径，访问会报 404 NoSuchKey）。
6. **建集合**：控制台数据库新建 `papers` 集合（`themes` 若不存在也一并创建；`members`、`member_items` 同样需创建）。集合权限保持默认私有即可，后台全部经云函数读写。进入后台点「导入官方 1 套 / 导入官方 10 套 / 导入官方 5 款」完成初始化。`feedback` 集合由小程序首次提交自动创建（若没有可手动建空集合）。
7. **反馈筛选索引**（使用「问题反馈」按状态筛选分页前需要）：控制台 → 数据库 → `feedback` 集合 → 索引管理，新增组合索引 **`status`（升序）+ `created_at`（降序）**。
8. **验证**：浏览器打开静态托管默认域名 → 输入密钥登录 →「数据看板」有数字、主题/版式列表可见即通；左侧「💬 问题反馈」能看到小程序端提交的反馈，可展开看全文与截图、标记已处理或删除。

> 任何板块改动后都要重新部署 `admin` 云函数，并把 `index.html` / `style.css` / `app.js` 三个静态文件重新上传到静态托管根路径覆盖（排序逻辑与「👑 会员」标记横跨云函数与前端：云函数没重新部署时列表不会带 `premium` 标记，标签就不会出现）。

官方主题已收敛为「小王子」一套（唯一有信封素材，也是未知 theme_id 的回落款）。历史版本曾 seed 6 套无信封素材的官方主题，**它们可能仍留在云数据库里**：`theme` 云函数只按 `status='online'` 下发，所以代码改动不会让它们消失，线上会继续出现这 6 套选择卡。

## 会员管理说明（2026-09，后台预置 + 小程序真实支付）

- **members 集合**：VIP 用户状态，按 openid 一对一：`{ _openid, state:'vip'|'free', level:'month'|'quarter'|'year'|'custom', plan_name, expires_at, renew, total_days, granted_at, granted_by, updated_at }`。后台「开通/续期」由 `memberGrant` 写入（granted_by='admin'）；小程序真实支付发货由 member 云函数写入（granted_by='xpay'），两条链路共用一张表。`total_days` 为累计会员天数，驱动 VIP 等级称号分档（寄字/守候/长情）。
- **member_items 集合**：专属版式（kind='paper'，存 colors）与专属主题（kind='theme'，存 swatch + 可选 `assets` 信封素材），**已真实接入小程序**：`theme` 云函数下发时并入主题/版式列表（premium 标记），写信第二步/详情/分享三端以通用专属模板渲染（取色 bg/ink/gold，后台改配色即生效），非 VIP 写信页见锁定款（🔒，点击引导开通）；会员页点击专属信纸可预览真实版式渲染示例，专属主题配置 `assets.envelope` 后会员页/写信页显示真实信封图（留空回落默认信封，卡片显示色样）。seed 与 `miniprogram/pages/member/premium.js` 同源手工同步（改色请两处一起改）。
- **member_orders 集合**：会员订单（待支付/已发货）。member 云函数 `subscribe` 下单落 created；云开发「消息推送」把 `xpay_goods_deliver_notify` 推回后按 out_trade_no 幂等置 delivered 并写 members。
- **小程序端已接入真实虚拟支付（个人·道具直购）**：`services/member.js` 云端 `getMembership` 走 member/get、`subscribe` 走 member/subscribe → `wx.requestVirtualPayment`；**未配置时下单接口明确返回「支付未配置」，云端模式不发放会员**（演示态仅在 `USE_CLOUD=false` 本地模式生效），后台预置的 VIP 状态与专属内容不受影响。
- **用户管理**：新增 `status='banned'`（后台封禁）与 `banned_at`；`user` 云函数 `ensure/getProfile` 对封禁账号返回 `banned` 错误，小程序端 `services/user.js` 弹窗提示并阻断。「注销」仍物理删除全部数据（现含 members/member_orders 记录）。

## 会员中心真实支付部署清单（member 云函数）

小程序端已写好真实支付代码，要真机跑通需完成以下部署配置（未完成则下单报「支付暂未开通」，不影响其它功能，也不会发放会员）：

1. **开通虚拟支付（个人）**：确认小程序主体为个人、服务类目含「工具」、已完成认证与备案；MP 后台 → 虚拟支付 → 开通 → 签约。记下 **OfferID** 与 **现网 AppKey**（虚拟支付 → 基本配置）。
   - ⚠️ **密钥轮换（必做）**：历史版本 `cloudfunctions/member/config.js` 曾把真实 AppKey 硬编码并提交进 git，该值须视为**已泄露** —— 请在 MP 后台「虚拟支付 → 基本配置」重新生成 AppKey（必要时一并更换 OfferID），再按第 4 步配置环境变量。代码内已移除全部兜底密钥，只读环境变量。
2. **创建并发布道具**：MP 后台 → 虚拟支付 → 道具管理，创建三档一次性道具（**月卡 ¥9.9 · 31 天 / 季卡 ¥25.9 · 93 天 / 年卡 ¥99.9 · 366 天**），把三档 productId 填入 `cloudfunctions/member/config.js` 的 `PRODUCTS`（价格以 MP 后台为准，代码 goodsPrice 单位为「分」）。道具发布后约 10 分钟生效。
3. **部署 member 云函数**：微信开发者工具 → cloudfunctions 目录 → 右键 `member`「上传并部署：云端安装依赖」。
4. **配置环境变量**：控制台 → 函数 member → 配置 → 环境变量，新增 `XPAY_OFFER_ID`（OfferID）、`XPAY_APP_KEY`（现网 AppKey）与 `XPAY_APP_SECRET`（小程序 AppSecret，MP 后台 → 设置 → 开发设置获取；`code2Session` 不支持云调用，需用它 HTTPS 直调换取 sessionKey 算签名）。
5. **绑定发货推送**：开发者工具 → 云开发 → 设置 → 其他设置 → **消息推送** → 推送模式选「云函数」→ 添加配置：消息类型 `event`、事件类型 `xpay_goods_deliver_notify`、云函数选 `member`。member 云函数按 `event.Event` 识别该推送并发货，返回 `{ErrCode:0}`（非 0 平台会重试，最多 15 次）。
   - ⚠️ **来源白名单（必做）**：客户端 `wx.cloud.callFunction` 也能伪造整个 `event.Event`，**仅靠订单绑定无法阻止攻击者给自己免费发货**（正文与订单都可为其自造）。member 云函数已把订单作为发货唯一事实来源（校验归属人/商品/金额/状态），而**唯一有效的代码侧封堵**就是在云函数日志中查看真实推送的 `[member] 发货推送来源 source=...`，把该 source 值配进环境变量 `XPAY_NOTIFY_SOURCE`（多个用逗号分隔）。配置后一切非平台来源的 `Event` 调用会被直接拒绝。**未配置前，伪造发货仍然可行**；如需更强保障，可另接入服务端向微信支付查询订单状态作为最终校验。
6. **iOS（可选）**：iOS 支付需微信 ≥ 8.0.68（代码已前置校验）；如需 iOS 端，另在 MP 后台配置小程序简称并开通苹果 IAP 支付。
7. **验证**：沙箱环境（env=1，需在 MP 后台沙箱配置加测试号）或小额真单：下单 → wx.requestVirtualPayment → 支付 → 收到发货推送 → members 翻 vip → 会员页轮询翻亮。后台「会员管理」可见该用户 VIP 记录（granted_by='xpay'）。

## 小程序侧联动

- 小程序 `services/theme.js`：`getThemes` / `getPapers` 云端模式分别调 `theme` 云函数的 `list` / `papers` action，只取 `status='online'` 文档；云端为空或失败回落本地内置配置，小程序永不被后台改动打挂。
- 信件锁定创建时的 `theme_version` / `paper_version`；老信件遇到已下架/已删除的版式按未知 id 回落第一套（留白志）渲染。
- 下架某主题/版式只影响新写信件的选择列表，不影响历史信件阅读。

## 更换云开发环境

同时改三处：`admin/app.js` 顶部 `CONFIG.API_URL`（重建路由）、`miniprogram/config/env.js` 的 `CLOUD_ENV`、新环境的云函数部署与 `papers`/`themes` 集合。
